Engineered CatBoost for imbalanced chronic kidney disease screening

A CatBoost pipeline, tuned to keep sensitivity high on a heavily imbalanced dataset, compared against Logistic Regression, Random Forest, XGBoost and SVM under one train, validation and test framework.

Research objective

Class imbalance

About 92% of the records are CKD cases. A model can score high accuracy by labelling everyone as CKD, so accuracy alone says little.

Sensitivity first

In screening, a missed case costs more than a false alarm. The study requires at least 92% CKD sensitivity, then looks for the best performance on the minority non-CKD class.

Method

  1. Preprocessing. Identifier and provider columns are removed, values converted to numeric and missing values filled with the median.
  2. Feature selection. Fifteen weak features, identified by agreement between Random Forest, XGBoost and Logistic Regression importances and checked against KDIGO guidance, are dropped.
  3. Stratified split. 70% training, 20% validation and 10% testing, preserving the class ratio in each part.
  4. Imbalance handling. Balanced class weights make errors on the rare non-CKD class count more during training.
  5. Model training. CatBoost (depth 6, learning rate 0.03, L2 regularisation 6, early stopping on validation AUC) and four baselines are trained on the same data.
  6. Threshold optimisation. On the validation set, the decision threshold with the highest balanced accuracy is chosen among those keeping CKD sensitivity at 0.92 or above.
  7. Evaluation. Every model is scored once on the held-out test set with screening metrics, and the CatBoost model is interpreted with feature importance and SHAP values.

Limitations

  • The analysis uses a single dataset and has not been validated externally or prospectively.
  • The optimised threshold needs to be evaluated on an independent dataset.
  • Feature importance does not establish causal relationships.
  • The model is a research prototype and is not intended for clinical diagnosis or deployment.

Team and code

The work was completed by a two-student research team under faculty supervision. Abu Adnan Shad led the model architecture, implementation and results analysis. A conference manuscript based on the thesis is being revised for submission.
